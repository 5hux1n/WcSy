## 项目想做什么

WcSy 是一个实验性的微信 iOS 插件。目标是在用户开启的聊天中，分析新收到的对方文字消息，并在对应消息下方显示仅本机可见的 JEV 情景判断。

当前优先完成 **JEV 分析、消息挂载和持久化**。候选回复、DeepSeek 生成与输入框填入的部分源码仍保留，但相关入口暂时关闭。

## 当前实现情况

以下是代码中已实现的内容，实际运行效果仍需继续验证：

- **逐聊天开关**：单聊、群聊分别启用；资料页和聊天右上角“咨询”提供入口。
- **自动分析**：尝试识别新收到的对方文字消息；自己的消息不作为分析目标，但可作为上下文。
- **多轮上下文**：最多 100 条当前聊天已加载记录、约 16,000 字符，包含匿名参与者、会话顺序、时间间隔和缺失标记。
- **14 维判断**：情景、意图、关注点、消息指向、回应期待、字面与语境、情绪线索、对话变化、压力、时限、约定状态、敏感领域、依据充分性和信息缺口。
- **判断结果**：展示模型选项分布与可能的备选解释，去掉具体回复建议和行动策略。分布不等于已确认的真实动机。
- **本地预览**：决策以紧凑引用式视图附在消息行下方，点按查看完整内容；尝试贴近原消息内容底部。
- **决策保存**：按会话与消息 ID 保存，磁盘保留最近 30 天、每会话最多 50 条。
- **聊天内状态**：在“咨询”菜单中查看当前阶段、等待时间、队列数量和最近结果，与“重新分析”按钮放在一起；菜单打开时自动刷新。

## 已知问题与未完成项

1. **新消息分析仍需验收。** 用户曾报告 0.2.23 新消息没有出现决策。后续修复了消息游标漏检测、占位消息提前消费、延迟时间戳和请求队列卡住的代码路径，但尚未确认全部覆盖实际故障。
2. **消息挂载与间距仍需真机调整。** 单元格复用、返回聊天、连续来消息、群聊和已有原生引用的组合仍待验证。
3. **尚未复用微信完整原生引用组件。** 当前是插件自己的本地视图，尝试读取可见引用视图的外观属性；读取不到时使用备用样式。
4. **不是完整聊天记忆。** 只读取当前已加载窗口，不会主动读取全部历史。更早的约定、媒体内容和不可读的引用正文可能缺失。
5. **新版提示词尚未完成线上效果评测。** 10 组情景测试验证请求结构与预期选项是否合法，不代表模型已经在这些场景中给出正确判断。
6. **多账号和消息 ID 重用尚未处理完整。** 持久化尚未增加微信账号命名空间，相关场景未验证。
7. **仅针对有限环境开发。** 目前代码尝试适配微信 8.0.78，并检查私有方法签名；不能保证其他版本或插件组合可用。

## 配置与使用入口

1. 在微信插件管理器中打开“WcSy 决策咨询”；没有匹配的管理器时，尝试“我”页右上角的备用入口。
2. 填入自己的 JEV API Key，保存并启用。当前接口是 TypeSafe `https://api.typesafe.ai/v1/systemone`，模型为 `jev-latest`。
3. 在对应聊天的资料页或右上角“咨询”中启用该聊天。
4. 保持当前聊天打开，接收对方文字消息；可在“咨询”菜单查看实时状态或手动重新分析。

API Key 保存在本机 Keychain。分析会把所选聊天窗口内的文字上下文发送给 JEV；它不是纯离线功能。图片、语音等媒体文件不上传，未知内容使用占位表示。决策不会作为微信消息发送，也不会写入微信聊天数据库。

## 本机构建

当前构建脚本面向 macOS 开发环境，需要 Xcode 命令行工具、Theos、RootHide Theos，以及 `dpkg-deb` 等打包工具。

脚本默认路径：

- rootless：`~/theos`
- RootHide：`~/theos-roothide`
- 两套工具链各自使用 `sdks/iPhoneOS16.5.sdk`

```sh
sh scripts/test-core.sh
sh scripts/test-jev-scenarios.sh
sh scripts/build-both.sh
```

构建输出到 `dist/`，脚本随后解包校验并提取注入文件。工具链与 SDK 不随仓库提供。当前 `.gitignore` 仅放行 0.2.25 快照产物，记录后续版本时需同步调整。
