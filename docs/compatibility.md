## 0.2.18 改动与本机验证

- 从微信消息单元格的 `cellView.viewModel.messageWrap` 读取本地消息 ID，并从 `isSender` 区分自己与对方。新文字消息先入队；消息行尚未渲染时最多等待 15 秒，避免第一次轮询就永久漏掉。
- 只要求 JEV API Key 才能开启逐聊天咨询。聊天页“咨询”菜单可重新分析最近一条已确认来自对方的文字消息，以便重试。设置页显示无正文、无联系人 ID 的 JEV 阶段或错误码。
- JEV 决策引用卡显示回复必要性、意图、语气、风险与建议动作，来自已校验的五字段结果。只在对应对方消息行显示，定位失败时不显示浮动卡。
- `sh scripts/test-core.sh`：覆盖上下文、隐私门控、JEV 响应解析、过期结果与草稿状态机。适配层 UI Hook 仍需设备验证。
- `sh scripts/build-both.sh`：检查双架构 dylib、安装路径、包名、Filter、弱链接及 RootHide rpath。

- [ ] 切换会话、离开页面或关闭此聊天后，迟到结果不显示在其他聊天。
- [ ] 大字体、深色模式、滚动、键盘、弱网与超时下聊天页仍可正常使用。

`CompatibilityManifest.json` 的 `supported` 仍为空，8.0.78 保持 `experimental`。0.2.18 已编译和检查安装包，**没有本版本的真机成功证据**。

2026-09-29 设备探针：USB 与 Frida 可连接。用户使用巨魔向 `WeChat.app/Frameworks/WcSy.dylib` 注入；最新探针确认已加载 0.2.18。用户确认决策文字出现，但离开聊天再返回后消失。0.2.19 将决策按会话和消息 ID 存入应用支持目录，重进聊天时恢复，待用户注入后验证。微信原生 `MMInputMsgReferView` 是输入框引用预览，不适合直接挂到收到的消息下方；当前展示仍为附着在微信消息行上的本地视图。

2026-09-29 后续真机探针：0.2.19 已由用户注入并运行，应用支持目录里有决策文件；返回聊天后插件仍识别缓存对应的对方消息，但可见行没有立即重新映射。用户滑动后确认决策重现。0.2.20 在消息单元格交给插件时直接记录行映射，列表暂时没有可见单元格时保留已有映射，并在重新分析完成时原位更新文字与行高。待用户注入验证。

0.2.21 增加对 `MMInputMsgReferView` 背景色、文字视图颜色及字体、容器圆角的运行时读取，应用于本地决策卡；如果微信没有提供某项属性，则继续使用系统样式。设置页显示实际读取结果。这借用的是引用视图外观，不会创建真实的引用消息。待用户注入后视觉验证。

0.2.22 根据用户提供的实际聊天截图，改为窄幅单行引用式预览，字号与间距靠近微信引用条；点按预览弹出完整决策。原先多行卡片在聊天中占据过多高度。该布局待用户注入验证。


### 0.2.23 代码复审

### 0.2.25：聊天内查看状态

咨询菜单在“重新分析最近的对方消息”按钮上方实时显示当前阶段、请求等待秒数、待处理数量、最近一次结果与时间。每 0.5 秒刷新；请求进行时禁用重复分析，结束后恢复。设置页仅保留兼容信息与入口提示，不再显示离开聊天后被改写的分析状态。

最近结果与状态按当前聊天 overlay 保存，避免其他聊天的全局状态串入；菜单关闭后停止状态刷新，聊天分析保持原有生命周期。该 UI 变更通过双方案构建和包内容校验，未安装到手机，实际展示待验证。
