# 0.2.24 变更与验证

## 多场景 JEV 判断

- 上下文从最多 20 条/4000 字符扩展至 100 条/16000 字符；包含双向消息、匿名参与者、时间间隔和信息缺失标记。
- 五字段回复决策替换为 14 维情景判断，解析并展示真实选项分布和可竞争的解释。
- 删除具体建议、回复策略和语气推荐；旧记录在展示时过滤过时建议。
- 提示词和限制详见 [JEV 提示词设计](jev-prompt-v2.md)。

## 新消息无法出现决策

用户报告 0.2.23 新消息没有新的决策。本次未连接到手机，尚未确认设备上的具体原因。代码检查与测试确定了以下会漏处理或卡住队列的路径：

1. 只比较列表最后一条 ID，插在未变化尾行前的新消息不会被消费。改为扫描窗口内未见消息，结合时间及本地 ID 判断新到达记录。
2. 文字占位在正文加载前被消费、延迟投递的时间戳低于游标，也会漏掉。增加对应回归测试。
3. JEV 请求返回时视图暂时脱离 window，旧代码会在释放 `analysisInFlight` 前返回。现在先释放队列，再判断是否能展示。
4. 超过 35 秒未完成的请求取消并释放队列。网络、超时及临时会话校验失败最多补一次重试；认证和结果格式失败不自动重试。
5. 分析快照保留会话观察顺序，避免延迟投递的旧时间戳改变目标位置。
6. 历史中暂不可读的消息保留为缺失占位，不再使整个上下文读取失败；尚未加载正文的文字不会被提前消费。

新增不含正文/账号/密钥的日志：入队数、请求开始、结束错误码、页面是否可见、队列超时恢复。

## 引用条间距

改为读取消息单元格中已有文本、气泡及引用内容的边界，JEV 条优先放在其下方 2 pt，按原内容起点对齐。无法定位内容边界时，使用微信原始行高作保守回退。行高预留由预览高度加 8 pt 减至加 4 pt；在高度未预留前暂不显示，避免覆盖气泡。

这是本地视图定位优化，尚未真机验证边界识别成功率，也不宣称复用了微信完整原生引用组件。
